# iPadの本棚・閲覧画面

2026-10-19。既存ユニバーサルアプリの画面を改善。認証・資料取得・端末保存・整理同期の契約とデータ形式は変更しない。

## 操作と配置

クラウドのプレゼン資料／図解ライブラリでは、通常文字サイズ・regular幅・横幅760pt以上で左260ptの本棚を表示する。フォルダを直接選択し、検索・グループ・タグでAND絞り込みできる。選択フォルダの作成・解除、資料の選択・一括移動は既存Storeを利用する。フォルダ選択や回転で整理設定を作り直さない。

compact幅またはアクセシビリティ文字サイズでは右下のメニューへ切り替える。regular幅で760pt未満は既存の上部操作を使う。選択中の操作行は横スクロールでき、移動先・完了に到達できる。検索はCommand-F、更新はCommand-R。

資料閲覧はregular幅で従来のツールバー・PDFページ一覧を利用し、compact幅またはアクセシビリティ文字サイズでは右の資料メニューと左上の閉じる操作を使う。iPadの起動・閲覧開始・全画面終了・資料を閉じる際に横向きを強制しない。iPhoneは既存の横向き専用動作を維持する。非表示の説明は「この端末」に統一。

## 検証

- iPad Pro 11インチ M5 / iPadOS 26.5 Simulatorで通常署名の67 XCTest合格（失敗0）。実機向けgeneric iOSビルドも成功。Xcode 26.5 SDK、arm64、ONLY_ACTIVE_ARCH=YESで実行。
- モック資料で縦横の本棚、フォルダ作成・選択・資料移動、PNG通常表示／全画面開始・終了／回転を操作確認。縦向きのまま開始でき、終了後も現在の向きを維持する。
- アクセシビリティlarge文字サイズで、本棚が引き出しに切り替わり、検索・フォルダ・分類操作へスクロールで到達することを確認。確認後文字サイズをlargeへ戻した。
- git diff --check合格。
- tools/verify_project.pyは変更前から存在する共有LibraryOrganizationパッケージを旧「パッケージなし」条件で拒否する。今回の変更にSwiftファイル／プロジェクト登録の追加はない。この旧スクリプトの合格とは扱わない。

最初の署名なしSimulatorテストではKeychain関連2件が認証エラーになった。通常署名で最終コードを再実行し67件すべて合格した。最初の全アーキテクチャ実行では共有Swiftモジュールのtarget不一致があり、上記arm64指定で解消。

証跡：outputs/ipad-layout/のテスト・ビルドログと画像。実iPad接続なし。実iPadでのログイン・整理同期・オフライン、実ウィンドウ縮小、PDF/PPTXの手動操作、外部ディスプレイは今回未検証。既存67件の自動テストには認証・保存・オフライン・同期の回帰検証を含むが、iPad実機での成功を保証するものではない。
